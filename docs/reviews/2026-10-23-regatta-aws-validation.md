# 観戦レースのAWS通し検証（2026-10-23）

対象: [003](../../specs/003-regatta-spectator/spec.md)・`SnipeRegattaStack`（東京）。手順は[AWS検証](../../specs/003-regatta-spectator/aws-validation.md)。

## 構成

CloudFront＋非公開S3、Cognito（Code＋PKCE、scope `regatta/race`）、HTTP API（全ルートJWT）、VPC Link→Cloud Map→Fargate 16 vCPU/32 GiBのDecider、Bedrock Nova Liteの振り返りLambda。ALB・NATなし。ワーカーは既定0台。

## 確認できたこと

| 確認 | 結果 |
| --- | --- |
| 未認証・不正トークン・偽の利用者ヘッダー | `/health`・`/decide`・`/debrief`とも401 |
| CORS | CloudFrontの配信元だけ許可。他の配信元には許可ヘッダーなし |
| ワーカー起動 | 0→1で約3.5分（イメージ取得＋モデル読込とウォームアップ）、ECSヘルスチェックHEALTHY |
| 本人のサインイン | ブラウザーで本人が登録・サインイン。`/health`がreadyになり、実Deciderを選択可能 |
| 実レース（風の振れ、予想Zephyr） | 4艇完走。Aurora 1:41、Jade 1:44、Zephyr 1:55、Coral 2:00。予想は不的中と正しく表示 |
| 実Deciderの判断 | API経由の`/decide`は47件すべて200。応答p50 2.3秒・p95 2.7秒・最大2.8秒（6秒期限内）。タック・針路維持・ジャイブが適用された |
| 期限外の扱い | Jadeのフィニッシュ後に届いた判断は「不採用」となり適用されなかった |
| 振り返り | Nova Liteが日本語で生成。参照`[D1]`〜`[D46]`は判断ログに存在する番号のみ |

ジャイブの選択はローカル検証では未観測だったが、このレースで初めて適用された。

## 見つかった不具合と修正

最初のレースでは判断2件がサーバーで410（期限切れ）となり、連続失敗の規則どおりレースが停止した。
推論は約3.06秒で終わっていたが、撮影用Macの時計が4.0秒遅れていた（`sntp`で+4.03秒）。
ブラウザーの絶対時刻`expiresAt`をサーバーが比較していたため、実際の残りは約2秒しかなかった。

サーバーは受信時刻からの6秒を自分の単調時計で判定し、ブラウザーの時刻を信用しないよう修正した（`812d343`）。
ブラウザー側も従来どおり自分の経過時間で破棄する。修正後のレースでは期限切れは0件。
修正の再デプロイ中に`/health`へ503が2件あった（タスク入替え中）。

## 未確認・制約

- 1レースだけの確認。期限超過の頻度・複数レースでの安定性・別端末は未測定。
- 振り返りの参照番号は存在確認のみで、文の内容が判断ログと一致するかは自動検証していない（例：各艇の操船の要約）。
- 16 vCPUの稼働は約$0.99/時。ワーカーは撮影後に0台へ戻す。
- イメージは計測用スタックのECRに`decider-v2`タグで置いている。計測用スタックを削除するとイメージも消える。
