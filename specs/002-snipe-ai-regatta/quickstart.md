# 実装後の検証手順

2026-10-22。ローカル練習は実装済み。実Decider・新API・AWSは未接続。旧アプリのテスト成功を新ゲームの検証として報告しない。

`pnpm install --frozen-lockfile`後、`pnpm --filter regatta-web dev`で起動し、[練習画面](http://127.0.0.1:5174/)を開く。
「風のシナリオ → 変化する海面」で約20秒周期の風向・風速と移動ブローを試す。濃い円は増風域。
進行はシミュレーション時間。一時停止では両艇と海面が止まり、同条件の再戦・記録再生では同じ風になる。
従来の一定風・振れ・ブローも個別練習として残す。

描画は画面右上で「追従／艇上／俯瞰」を切替。追従は帆・水平線・引き波、艇上は風上舷から前方を確認できる。
重い場合はヘッダーの「高画質→軽量」を選ぶ。OSの動きを減らす設定では波・艇の揺れも抑える。
画質・視点は艇性能や記録の再現性を変えない。表示の波はゲーム用演出で、波乗りの物理は未実装。

## ローカルの順序

1. `packages/sailing-sim/`を追加後、`pnpm --filter sailing-sim test`で一定風・角度境界・風上失速・タック損失・回航・同tickフィニッシュを検証する。
2. `apps/regatta-web/`追加後、`pnpm --filter regatta-web dev`で単艇練習。本人が一定風・振れ・ブローを試し、G1の評価と調整値を記録する。
3. 旧ローカルモデルを固定revisionで再利用して新戦術評価ハーネスを作る。AWS通信なしで100判断の遅延と候補外出力を計測。G2を満たすまでクラウド公開へ進めない。
4. 同条件20組でルール艇と実モデル艇を比較する。勝率だけでなく完走・時間・待ち・fallback率を記録。選択を入れ替えると航路が変わることも確認する。
5. 新API実装時にOpenAPI草案を正本化し、Connexion検証・Orval生成・契約テスト・mockブラウザー検証を追加。未認証・他人・quota・再送・期限・中断の拒否を確認する。
6. タブ非表示→復帰、通信遅延、古いepochの返答、生成失敗を注入し、艇の早送り・late result適用・有料無限再試行がないことを確認する。
7. 保存記録の再生では外部モデル通信が0件で、同じ版の入力とsnapshotが一致することを確認する。

## AWS検証前のゲート

- 旧環境は削除済み。旧CloudFront URLやCognito IDを新環境へ埋め込まない。
- 新スタックのdiff、最新価格と既存$30総予算の残額、30時間の残稼働枠、停止・削除手順を確認する。
- 新scope・所有権・同時1・日次quota・記録削除を先に検証。ログにトークン・ユーザー入力を出さない。
- 新環境をデプロイする工程で、実モデルの観測→適用遅延、失効、終了後の抑止、Bedrockの参照整合を計測する。
- 使い終わったら受付停止・drain・タスク0を確認。撮影時だけ準備済みのワーカーを起動する。

## デモの合格条件

人間が操船し、風の変化→実Deciderの選択→AIの航路変化→ゴール→記録に基づく振り返りまで見せる。
mock、固定ルール、実モデル、編集による待ち時間短縮を区別する。公開動画は3分未満。
