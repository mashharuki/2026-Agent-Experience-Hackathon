# 一手を比較し、本人が選んだ一枚を持ち帰る体験

2026-10-19。ユーザーは[方向性の案](../../docs/reviews/2026-10-19-product-direction-options.md)の**①選んだ一枚を持ち帰る＋③一つだけ変えて比較する**を支持。以下に設計と検証条件を記す。T141〜T145はローカル実装・検証済み。[実装結果](../../docs/reviews/2026-10-19-photo-completion-validation.md)を参照。実機・AWS・利用者評価は未実施。

## 体験の約束

一枚撮る → 根拠と希望があれば一手だけ試す → 条件を合わせて撮り直す → 本人が比較する → 選んだ写真を任意で保存して終了する。

外見を採点せず、前の写真を選ぶ・変更しない・保存しないで終了することも成功と扱う。撮影用途は固定せず、プロフィール写真は説明・検証の一例にする。案②の新モード、案⑤の撮影者との共有は採用しない。

## 最初の範囲

四画面と既存の四択、最大二変更・三解析を維持する。主な追加は端末内の撮影ガイド・比較表示・保存操作で、OpenAPIやAWSの画像保持を変更しない。

| 場所 | 追加する体験 |
| --- | --- |
| 相談する | 「撮る・一手試す・比べる・選んで保存」という見通しを短く示す。必須入力項目を増やさない |
| 撮り直し | 基準写真を参考にできる任意の位置合わせガイド。左右向き・縦横比を揃え、非表示にもできる |
| 比べて選ぶ | 既存の並置にA／B切替を追加。写真名と同じ表示枠を維持。画像を変形・美化して差を作らない |
| 保存 | 本人が指定した前／後の撮影Blobを端末から保存。比較前の一枚でも保存できる経路を設け、無変更の選択を尊重する |

「差が分からない」はどちらかの保存を自動選択したことにしない。保存対象の指定と、サーバーへ送る好みのフィードバックは別のローカル状態として扱う。写真を保存するためにフィードバック通信の成功を必須にしない。

保存は終了前の任意操作とし、終了を保存待ちで塞がない。終了時には既存どおり撮影データ・参照URLを解放し、遅延応答で復活させない。アプリが既に書き出した本人のファイルまで削除できるとは説明しない。

最初の実装は現在表示している比較ペアからの保存。過去全ペアの写真アルバム、アカウントへの画像保存、自動共有は含めない。もう一手に進む場合も、保存は本人が必要な時に行う。

## 技術・データの扱い

[技術一覧](../../docs/tech-stack.md)のReact／MUI／TanStack Query／Vitest／Playwrightを維持する。撮影・画像参照は`features/camera/`と`features/session/photos.ts`を活用し、保存処理は端末内の小さなヘルパーへ分離する。

- 保存対象は端末にある撮影Blob。比較のスクリーンショット、ガイドやラベルを合成した画像を誤って書き出さない。センサーの元解像度・画質は保証しない。
- 保存要求は本人の操作で開始する。[download属性](https://developer.mozilla.org/en-US/docs/Web/API/HTMLAnchorElement/download)を使う場合も、実際に端末へ保存されたと無条件に断定しない。対応端末の操作確認を後段に残す。
- 参照URLは処理中に早く解放しすぎず、不要になったら[revokeObjectURL](https://developer.mozilla.org/en-US/docs/Web/API/URL/revokeObjectURL_static)で解放する。既存の前／後の同一参照の扱いを壊さない。
- 写真・ガイドはメモリ内に限定し、サービスワーカー・localStorage・IndexedDBへ自動保存しない。本人によるダウンロードだけを明示的な書き出しとして区別する。
- ガイドは位置合わせの参考であり、同一照明や比較可能性を保証しない。自動補正、顔の形の変更、規格判定は行わない。
- 助言数・画像送信・Bedrock呼出しを、このUI追加のために増やさない。保存でS3へ再送しない。

## 実装と検証の順序

1. T141で比較・選択・保存・終了の画面内の流れを具体化し、合成写真で操作確認できる状態にする。
2. T142〜T144で撮り直しガイド、比較切替、任意保存・解放を実装する。
3. T145でローカルの画面・契約・モックE2Eを検証する。
4. [モデル実験計画](model-evaluation-plan.md)のT125〜T140を進める。今回のUI追加だけでモデル入力を変える必要はない。ラベルを固定する前にFR-030／031との整合を確認する。
5. 両方の結果を確認してT124のAWS・実機検証へ進む。ここでAWSを先行実行しない。

### 表示・保存・フィードバックを分ける

- `SessionFlow`が前後の`Photo`とセッション世代を所有し、各画面は参照を受け取る。保存用に写真を複製して保持しない。
- `Compare`は表示方法と表示中の前／後だけをローカル状態として持つ。表示切替は既存の`choice`を書き換えず、APIを呼ばない。
- 保存は「前の写真を保存」「後の写真を保存」の明示ボタンで対象を指定する。別の選択フォームを増やさず、押されたボタンの対象を保存ヘルパーへ渡す。`unclear`や一枚表示中の写真から対象を暗黙に決めない。
- フィードバック通信の待機・失敗と保存要求の案内を分離する。通信中でも保存・表示切替・終了を使えるようにする。
- ファイル名は`photo-before.jpg`／`photo-after.jpg`などの固定名とし、セッションID・希望文などを含めない。保存ヘルパーは`fetch`やストレージAPIを使わず、写真の参照URLを自分で破棄しない。

### 撮影・終了で守る境界

- 現在のライブ映像は左右反転表示、撮影Blobは非反転。ガイドもライブ映像と同じ反転・表示枠で全体を収めて描画し、比較・保存には非反転の撮影画像を使う。ガイドはDOM上に置き、`captureFrame`のcanvasには描かない。
- `captureFrame`やテスト画像の生成が終わる前に終了・画面破棄した場合、後続の`onCaptured`を適用しない。再開始した別セッションにも持ち込まない。
- 「もう一手」で後の写真を次の基準へ昇格する場合、利用中のURLを早く解放しない。置換・終了・破棄後には参照を残さない。
- 初回の`offer_finish`は現行サーバーで`DONE`に遷移するため、終了後に写真を残す設計には変えない。無変更での保存は解析前のプレビューと、終了前の助言画面で可能にする。自動終了後の保存復元は今回の対象外とし、案内でも約束しない。

## ローカル検証の一覧

| 検証 | 確認する結果 |
| --- | --- |
| 保存対象 | 前／後を異なる合成画像にし、各ボタンの保存内容が元Blobと一致する。表示中の画像や好みを変えても対象を取り違えない |
| 無変更・通信失敗 | 初回プレビューから保存できる。好みの送信が失敗・待機していても保存と終了が可能。「差が分からない」で自動ダウンロードしない |
| ガイド | 表示／非表示で撮影でき、ライブ映像と向きが揃う。実際の撮影処理がガイドを参照せず、出力に重畳しないことを合成映像で確認する |
| 比較 | 並置と一枚表示の双方でラベル・写真・好みを保持。キーボード操作と日英のラベルを確認する |
| ライフサイクル | 撮影中の終了、再開始、画面破棄、基準写真への昇格で、遅延画像の復活と不要なBlob URLの残留がない |
| 追加通信 | 保存・ガイド・表示切替の前後でモックAPI呼び出し履歴が増えない。通常の解析・フィードバック・終了通信とは区別する |
| ブラウザ | Playwrightでダウンロードイベントとファイル内容、保存せず終了を確認。OSの保存完了はこの結果から推定しない |

実装後に`pnpm --filter frontend test`、`pnpm --filter frontend build`、`pnpm --filter frontend lint`、`pnpm --filter frontend test:e2e`、`pnpm check:quality`、`pnpm exec biome check .`、`git diff --check`を実行する。既存の差分や失敗があれば今回の変更に起因するものと分けて記録する。今回のUI変更ではOpenAPI・生成クライアント・サーバーの状態契約を変更しない。

## 受け入れ条件

- 同じペアを並置とA／Bで表示でき、ラベル・画像・選択対象が食い違わない。切替だけで解析しない。
- ガイドは任意で、オフでも撮影できる。保存画像にガイドを焼き込まない。
- 前／後それぞれの保存要求が、そのBlobへ対応する。「差が分からない」を後の写真へ勝手に変換しない。
- 変更なしの一枚も保存を要求でき、保存せず終了する操作も常に可能。
- 保存操作の失敗で写真の選択を失わず、再操作か終了を選べる。ダウンロード要求を「保存完了」と偽らない。
- 終了・再開始・画面破棄で不要な参照を解放し、旧画像や遅延結果が新しいセッションへ混ざらない。
- 合成画像によるPlaywrightで前を選ぶ／後を選ぶ／保存せず終了を確認する。OSの写真アプリ等への保存の成否はモックの成功と分ける。
