# Implementation Plan: Snipe AI Regatta（仮称）

**Branch**: `main`（変更なし） | **Date**: 2026-10-21 | **Spec**: [spec.md](spec.md)
**Status**: 設計案。旧AWS環境は削除済み。ゲームは未実装・未デプロイ。

## Summary

「大学時代はクルーだった。今度は自分がスキッパーになり、AIと風読みで勝負する」。
ブラウザーでスナイプ級を題材とした艇を操船し、Strands Decider 2Bが戦術を選ぶAI艇と競う。
タック位置とコース選択が勝敗につながることを最優先にする。

初版は人間1艇対AI1艇、コース1つ、風上マーク左回り→風下のフィニッシュ。
2〜3分を目標にし、180シミュレーション秒で打ち切る。これらは設計値であり実測ではない。
全競技規則、沈起こし、フルトリム、多人対戦、AIクルー、現実の気象連携は後続候補。

## プレイ体験と画面

1. **ロビー**: ローカル練習／クラウドAI対戦、操作説明、ワーカー準備状況。対戦は認証後に利用。
2. **レース**: 斜め上方の追従視点＋戦術俯瞰へ切替。風向・風速・艇速・VMG・マーク・航跡。
3. **結果**: 順位、完走／時間切れ、航跡、判断マーカー、再戦。生成解説は非同期で後着。

操作案はA/Dでラダー、W/Sでメインシート。タック／ジャイブ補助も同じ最大舵角・回頭速度を守る。
メイン自動トリムは両艇で同じ設定を選び、プレイヤーは手動へ切替可能。ジブは自動。
補助は表示し、操作の完全な対称性とは呼ばない。AIの戦術詳細は結果画面で見せる。
ブローは海面の模様と俯瞰表示で読めるようにし、AIへ渡す可視範囲と一致させる。

## 帆走モデルとコース判定

- 物理座標は東+x、北+y、m・s・m/s、内部角rad。表示方位は北0度・時計回り。
- 風向表示は吹いてくる方角。内部の真風ベクトルは流れる方向。`apparentWind = trueWind - boatVelocity`。
- ポーラは真風速・真風に対する艇首角→目標艇速の近似表。見かけの風をポーラへ二重適用しない。
- 見かけの風は帆の向き・トリム効率に使う。ポーラ、失速角、加減速、旋回抵抗、タック損失は版管理。
- 実測スナイプ性能表は未取得。初期曲線はゲーム用の仮定であり、実艇の完全再現・SCIRA認定とは表示しない。

固定tickごとに観測風→操作制約→旋回→艇速→位置→回航／接触判定の順で処理する。
タック減速は風位を横切る操船イベントに一度だけ適用し、角度の微振動で連続発火させない。
波・ヒールは初版では視覚表現中心。波乗り・乗員重心の物理再現は後続。

初版はスタート済みの状態から走る。回航は到達半径だけでなく、進入ゲート→指定側→退出ゲートの順で判定。
フィニッシュは必要マーク完了と線分の交差方向で判定。同tickは交差時刻を補間する。
コース外は境界へ戻る操船を要求。接触は双方共通の減速を行う簡易ルールで、公式RRSの裁定とはしない。
ポート／スターボードを含む全規則や抗議処理を省略していることを開始前に説明する。

## Deciderとコードの責任境界

版付きの問い `choose_sailing_tactic` で、実行可能な戦術ツールだけを候補にする。

| 選択肢 | 実行内容 |
| --- | --- |
| `hold_course` | 現在の目標針路・タックを維持 |
| `tack_now` | 逆タックで風上への目標針路を設定 |
| `seek_visible_pressure:<id>` | 可視ブロー候補IDへ寄せる。候補ごとに独立した選択肢 |
| `approach_mark` | 回航可能な範囲でマークへのアプローチへ移行 |
| `jibe_now` | 風下レグで反対のジャイブへ移行 |

コードはレグ・旋回中・場外・接触回避などで実行不能な操作を除外し、選択後に通常の舵制御で目標へ進める。
最速コースをコードが先に決め、モデルへ追認だけさせない。低レベル制御と戦術選択は別責務。
候補1つは `source=policy`、モデル値null。エラー・期限切れは `source=fallback`、以前の戦術を維持。
共通の場外・接触回避制御を優先し、モデル選択・実行結果・上書き理由を別々に記録する。
confidenceはヨット判断の正解率ではなく、未検証の閾値で最善手を保証しない。

## リアルタイム動作・時計・公平性

- 物理30Hz、描画は補間。ネットワーク応答は描画をブロックしない。
- 判断の開始間隔8秒以上、処理中1件、1レース最大24件。風の変化もこの制限を超えない。
- 観測tick・連番・epoch・要求IDを固定。観測から適用まで実時間3秒の期限を両端で検査する。
- 期限後、新しいレグ・旋回・epochと矛盾する返答は破棄。ワーカーも期限後に推論を開始しない。
- timeoutで既存推論が即時停止できるとは仮定しない。終了・破棄までサーバーの1件枠を保持し、次jobを積み上げない。
- 連続2回期限超過ならクラウド対戦を中断。ルール艇の練習は選べるが、実モデル対戦の完走に数えない。
- 180秒はシミュレーション時間、3秒は単調時計の実時間。タブ非表示で双方の艇・風を同時停止し、判断epochを失効。
- 復帰で早送りしない。サーバーのleaseは実時間10分で失効し、停止で無制限に利用させない。
- pause/resumeはcontrol APIで状態・epochを同期する。非表示時に通信できなかった場合はローカルで破棄を維持し、復帰時の同期完了前に再開しない。
- 艇性能・舵角・回頭・帆の応答・観測情報をそろえる。人間の連続操船とAIの自動操船＋間欠戦術判断の差は説明する。
- AIへ将来の風・生成seedを渡さない。画面で観測できるブローと風履歴だけを渡す。

**実験ゲート**: 旧Fargateの起動は約146〜162秒だったが、温まった判断の遅延ではない。
新しい問いで100回測り、p50/p95・待ち行列・失効率を分離する。p95≤2秒が未達なら状態・候補を調整して再評価。
未達のままリアルタイム対応済みとしない。戦術間隔の変更・双方同時停止モード等は体験が変わるため合意後に仕様更新する。

## AWS構成と信頼境界

[編集可能なAWS構成図](../../docs/architecture/diagrams/snipe-regatta.drawio) ／
[プレビュー](../../docs/architecture/diagrams/snipe-regatta-system.png)。新環境はまだ存在しない。

1. S3＋CloudFrontがSPAを配信。Cognito認証後にJWT付きHTTP APIへアクセス。
2. Lambdaが全体1レースのlease、所有者、quotaを原子的に確認してレース作成。
3. SPAが観測を送る。DynamoDBの冪等レコード・job・quotaを一括保存し、SQSへjob IDを配送。
4. Fargateが期限・状態を再確認し、Deciderでツール選択、条件付きで結果保存。
5. SPAはjob取得後、有効な返答だけを次tickへ適用。全量の艇状態を常時同期しない。
6. 完走記録を分割保存し、要求された場合だけBedrockで事後解説を生成。

競技状態の正本はブラウザーで、クライアント改変を完全には防げない。APIの所有権・課金防御は
サーバーで行うが、送られた艇位置の真実までは保証しない。公開ランキングは設けない。
競技性を高める段階でサーバー側シミュレーション・入力検証を別設計する。

## 記録・再生・事後解説

seedだけでは実モデル対戦を再現できない。物理／ポーラ／風の版、双方の操作、観測・受信・適用tick、
失効・fallbackを記録する。再生は記録された操作を使い、モデルを呼び直さない。
同seedの再戦は風条件を再利用するが、モデル結果・勝敗の一致は約束しない。

Bedrockへは上限付きの要約と参照IDを送る。名前・自由文は不要、1回・最大800出力tokens。
参照IDを検査し、存在しない場面は表示しない。「タックを選んだ。その後に差が縮まった」のように
観測と結果を述べ、内部の思考や勝因を捏造しない。別選択との比較は別途シミュレーションした場合だけ示す。

## セキュリティ・保持・費用

- 新scope案 `regatta/race`、全レース・job APIにJWT、所有者、状態の検査。
- 初期quota案は1人5レース/日、全体20レース/日、同時1、判断全体480回/日、解説20回/日。
- 冪等キー・連番・quota・job・状態を同じトランザクションへ入れ、二重配送で推論を増やさない。
- 終了・削除と結果保存は条件付きで競合制御。lease回収・未送信再配送・期限切れ回収を残す。
- 記録24時間、通常ログ7日。ログはID・enum・遅延・tokens等のみ。新構成に画像バケット・画像IAMは不要。
- 1要求64KiB、航跡は分割・合計512KiBまで。削除は失敗・残存件数を返し、削除中の新処理を拒否。TTLは即時削除ではない。
- 新スタック `SnipeRegattaStack` は既定desiredCount=0。利用時のみ起動、夜間停止・受付スイッチ・予算通知。
- **承認済み総予算$30・稼働合計30時間はリセットしない。** 旧利用分を含む残額を確認し、クレジット適用を推測しない。
- 10/17旧単価の参考式は `4×0.05056 + 16×0.00553 + 0.005 = $0.29572/時`。新見積もりではない。
  再デプロイ前に最新単価、ECR・配信・API等、残予算を積算する。

## Complexity Tracking

FargateはCPUでの既存起動実績を活かす例外。停止時0とし、常時課金を避ける。
WebSocket、ALB、NAT Gateway、GPU常時稼働は初版に追加しない。
Lambdaへのモデル同梱は起動・メモリ等の別検証が必要であり、現段階では採用しない。
