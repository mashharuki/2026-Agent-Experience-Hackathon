# Feature Specification: スナイプ級・人間対AIヨットレース

**Feature Branch**: `main`（設計のみ。新規ブランチは未作成）
**Created**: 2026-10-21
**Status**: Draft — 設計。ゲーム実装・操船検証・モデル評価・再デプロイは未実施。
**Input**: スナイプ級のクルー経験者が、スキッパーとしてタックや風上への帆走を楽しみ、AI艇と対戦できるゲームへ転換する。既存AWS環境を削除し、コードの再利用を検討する。

## User Scenarios & Testing

### User Story 1 — 自分がスキッパーとして走る (Priority: P1)

風を見ながら舵とメインセールを操作し、タックする場所を自分で決める。まず単艇練習で操船の手応えを確認できる。

**Why this priority**: 自分の判断で艇を走らせたい、という企画の出発点。対戦相手が未完成でも検証できる。
**Independent Test**: 同じ風の練習コースで針路・帆を変え、速度の変化とタック後の回復を観察する。

**Acceptance Scenarios**:

1. **Given** 一定風、**When** 風上へ直進しようとする、**Then** 自力で進み続けることはできず、タックを使って風上へ進める。
2. **Given** 帆走中、**When** タックする、**Then** 旋回・減速・再加速が連続して見え、瞬間的に向きだけが反転しない。
3. **Given** 操船中、**When** メインセールを調整する、**Then** 同じ針路でも速度が変わる。初版ではジブの操作は自動であると説明する。

### User Story 2 — AIスキッパーと競う (Priority: P1)

同じ艇性能・風の観測条件のAI艇と、風上マークを回って戻る短いレースで勝負する。

**Why this priority**: タックとコース選択の結果が相手との位置関係として現れる。
**Independent Test**: 同じコースで人間1艇対AI1艇を走らせ、AIが観測に応じて複数の戦術から選択し、実際に航路が変わることを確認する。

**Acceptance Scenarios**:

1. **Given** 風が振れる場面、**When** AIが判断する、**Then** 選ばれた戦術が操船に反映され、判断時点と実行時点が記録される。
2. **Given** レース開始、**When** 風と艇性能を比較する、**Then** AIだけに将来の風や隠れたブローの情報、速度上乗せが与えられていない。
3. **Given** AIからの返答遅延、**When** 期限を過ぎる、**Then** ゲームは動き続け、代替操船を表示する。期限後の返答は航路を変更しない。
4. **Given** 終了・中断済み、**When** 遅い返答が届く、**Then** レースを再開せず、新たな有料判断も受け付けない。

### User Story 3 — 勝負を分けた場面を振り返る (Priority: P2)

終了後に両艇の航跡、当時観測できた風、実際の判断を重ね、次のレースで試したいことを見つける。

**Why this priority**: 勝敗だけで終わらず再戦につなげ、AIの判断も説明できる。
**Independent Test**: 保存した合成レース記録を開き、任意の判断時点へ移動して航跡と観測値を表示する。

**Acceptance Scenarios**:

1. **Given** 完走した記録、**When** 振り返りを開く、**Then** 判断前の情報と判断後の結果を区別して表示する。
2. **Given** 生成解説、**When** 参照場面を開く、**Then** 対応する記録が存在する。AI内部の思考や、別の選択なら必ず勝てたという断定を表示しない。
3. **Given** 解説生成の失敗、**When** 結果画面を開く、**Then** 勝敗・航跡は見られ、有料生成を自動で繰り返さない。

### Edge Cases

- 風向の359度→0度の変化、無風に近い状態、風上での失速、連続タック。
- マークの逆回り、ゴール線の逆向き通過、コース外、艇同士の接触。
- 判断の二重送信、順序の逆転、通信断、モデルの不正出力、旧い観測への返答。
- タブ非表示、フレーム落ち、認証期限切れ、ワーカー停止中の開始、途中終了。
- 記録の改変、他人のレースID、解説中への命令混入、削除途中の失敗。

## Requirements

### Functional Requirements

- **FR-001**: 初版はデスクトップブラウザー、スナイプ級を題材にした同性能の2艇、プレイヤー対AIの1対1とする。
- **FR-002**: 舵・メインセール・タック／ジャイブを操作できる。ジブと乗員の動作は初版では補助されると明示する。
- **FR-003**: 風向・風速、艇速・針路、目標マーク、両艇の位置を表示する。風の振れ、移動するブロー、タックの損失をゲームの結果に反映する。
- **FR-004**: 風上への直進不能、タック・ジャイブ、風上／風下への進行を再現する。実艇の完全な流体解析・公式性能再現とは表示しない。
- **FR-005**: マークの指定側の回航と正方向のフィニッシュを判定し、完走・時間切れ・途中終了を区別する。
- **FR-006**: AIには意味のある複数の戦術を選ばせ、その選択を艇の動作につなげる。固定ルールだけで動かす練習艇を実モデル艇と表示しない。
- **FR-007**: 両者の艇性能と観測可能な情報をそろえる。AIの反応間隔や操船補助の差は説明し、公平性を検証せず保証しない。
- **FR-008**: 判断待ちで操船画面を停止しない。古い・重複・中断後の判断を適用しない。
- **FR-009**: 結果、航跡、判断、代替操船、観測時点を振り返れる。生成解説は記録に基づく事後解説として示す。
- **FR-010**: AWS上の有料処理と利用者のレース記録は認証・所有権確認・回数制限で保護する。
- **FR-011**: いつでも中断できる。中断後は有料処理の新規受付を止め、記録の削除操作を用意する。
- **FR-012**: 日本語・英語の案内と操作説明を用意し、キーボード操作とフォーカスを維持する。
- **FR-013**: 公式募集に沿って、実AWS実行、実モデルの判断、生成処理、公開コード、再利用可能な判断パターン、記事、3分未満の公開デモを準備する。

### Key Entities

- **Race**: 所有者、コース、風シナリオ、状態、開始・終了、勝敗、利用枠。
- **BoatState**: 位置、針路、速度、タック、帆の設定、回航の進捗。
- **Observation**: その時点で観測可能な風・艇・相手・目標。未来の風を含めない。
- **DecisionRecord**: 問いの版、観測、候補、選択、出所、適用または破棄、処理時間。
- **Replay / Debrief**: 航跡・操作・判断の時系列と、それを参照する事後解説。

## Success Criteria

### Measurable Outcomes

以下は受け入れ目標であり、達成済みの数値ではない。

- **SC-001**: 設計者本人が一定風・振れ・ブローの3条件を試し、「操船が成立」「タック位置を迷う」「もう一度走りたい」の各項目を具体的な場面とともに評価する。
- **SC-002**: デモコースは通常の完走が2〜3分を目標とし、最長180秒で結果または時間切れを表示する。コース長は操船実験で調整する。
- **SC-003**: 合成条件10件すべてで、未来の風の秘匿、同じ艇性能、中断後の判断破棄、禁止された操船の拒否が成立する。
- **SC-004**: AI判断を8秒以上空けて行えることを目指し、観測から画面での適用までの95パーセンタイルが2秒以内、3秒超の返答の適用が0件となる。
- **SC-005**: 評価用PCの通常表示で毎秒60描画を目標とし、毎秒30描画以上の時間が計測区間の95%以上となる。端末と画質を併記する。
- **SC-006**: 同じ条件の比較レース20組で、完走率・所要時間・判断待ち時間・代替操船率を記録する。AIの勝率の高さだけを合格条件にしない。
- **SC-007**: デモ1本で、実モデルが選んだ戦術と航路への反映を少なくとも1場面示す。生成解説と固定ルールの役割も区別する。

## Assumptions

- 名称は仮称「Snipe AI Regatta」。初版の数値・操作・コースは設計案で、プレイテスト後に更新する。
- 初版の風はゲーム内で生成し、現実の気象API・海流・実海域地図は使わない。
- 単艇練習はローカルで成立させる。クラウド対戦は初版では同時1レースとし、待機状態を表示する。
- ブラウザー上のシミュレーションを信頼する体験デモであり、不正防止された競技・公開ランキングは対象外。
- 沈起こし、完全な乗員体重移動、全セーリング競技規則、多人対戦、VR、AIクルーは後続候補。
- 本書は旧プロダクトの実装を削除・移植した証拠ではない。AWS削除と新設計の作成のみを今回行う。
